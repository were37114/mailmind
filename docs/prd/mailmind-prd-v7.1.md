## 一、产品定位
### 1.1 一句话定义
**MailMind 是运行在用户本地的 AI 邮件第二大脑**——自动下载全量历史邮件，用本地大模型构建个人邮件知识库，主动推荐基于邮件数据的智能任务（审批汇总、报价分析、周报生成等），让邮件从"信息洪流"变为"可执行洞察"。
### 1.2 核心差异化（vs Read AI / Clay / Superhuman）

| 维度 | MailMind | Read AI | Clay | Superhuman |
|------|----------|---------|------|------------|
| 数据主权 | **本地处理，原始邮件不离机** | 云端 | 云端CRM | 云端加速 |
| 核心能力 | **场景驱动型主动推荐** | 会议/邮件摘要 | 关系管理 | 邮件提速 |
| 知识库 | **个人邮件知识库（第二大脑）** | 无 | 联系人图谱 | 无 |
| 企业场景 | **审批/周报/报价分析闭环** | 通用摘要 | CRM场景 | 通用效率 |
| 模型架构 | **本地分层（0.5B+7B）+ 可选云端** | 纯云端API | 纯云端API | 规则+轻量AI |

### 1.3 目标用户（P0 → P1）

| 角色 | 核心痛点 | 高频场景 | 付费意愿 |
|------|----------|----------|----------|
| **企业高管**（P0） | 审批邮件漏处理、出差期间积压 | 审批汇总、紧急邮件识别 | 高（企业付） |
| **销售经理**（P0） | 报价/合同邮件散落、跟进遗漏 | 报价分析、客户邮件聚合 | 中高（个人+企业） |
| **项目经理**（P0） | 跨项目邮件碎片化、周报手工写 | 周报生成、待办提取 | 中（企业付） |
| HR/财务/行政（P1） | 面试安排、发票归档 | 信息提取、分类归档 | 中 |

### 2.2 场景推荐系统（核心卖点详细设计）
**设计原则**：从"被动工具"到"主动助手"
**MVP场景库（3类）**：

| 触发条件 | 推荐场景 | 模型参与 |
|----------|----------|----------|
| 未处理审批邮件≥3封 | "您有{N}封待审批，X封已超24h" | 7B精筛 |
| 周五16:00+本周汇报邮件≥2 | "生成本周工作周报" | 7B生成 |
| 3天未回复的讨论邮件 | "{N}封邮件待回复提醒" | 规则 |

**推荐排序算法**：
```plaintext
score = 0.35 × urgency_score + 0.30 × relevance_score 
      + 0.20 × history_score + 0.15 × frequency_score

反馈飞轮:
  👍: history_score += 0.1
  👎: history_score -= 0.2
  🔄: 同类型降权，下优先级上浮

```

## 三、技术架构（gstack评审后调整）
### 3.1 架构简化（6层 → 4层）

| 层级 | 组件 | 技术选型 |
|------|------|----------|
| UI层 | 独立桌面客户端 | Tauri + React |
| Core层 | 业务逻辑 | TypeScript |
| 模型层 | 0.5B/7B/Embedding | llama.cpp + ONNX Runtime |
| 数据层 | 结构化+向量+全文 | PGLite + pgvector |

### 3.2 技术选型（gstack:eng推荐）

| 组件 | 选型 | 理由 | 备选 |
|------|------|------|------|
| 桌面客户端 | **Tauri** (Rust+Web) | 比Electron体积小10x，性能更好 | Electron |
| 模型推理 | **llama.cpp** | 本地推理标准，跨平台，CPU/GPU都支持 | ONNX Runtime |
| Embedding | **ONNX Runtime** | 比Python推理快2-5x | transformers |
| 数据库 | **PGLite** (WASM) | 浏览器/桌面都能跑，无需安装Postgres | DuckDB |
| 向量索引 | **pgvector** | Postgres生态，Hybrid Search成熟 | LanceDB |
| 邮件解析 | **mailparser** (Node.js) | 成熟库，编码处理完善 | 自研 |

### 3.3 数据流设计
**新邮件到达**：
1. 同步引擎下载 → 存储原始.eml
1. 解析引擎提取元数据
1. 0.5B分类（同步，<500ms）→ 写入分类标签
1. 规则引擎匹配触发条件 → 写入事件队列
1. Embedding向量化（异步，后台）→ 写入向量索引
1. 7B分析（异步，后台）→ 仅重要邮件触发
**用户查询**：
- 自然语言 → 语义检索（向量索引）
- 结构化 → SQL查询（PGLite）
- 场景推荐 → 规则匹配 + 模型推理
### 3.4 核心Schema
**邮件主表**：id, message_id, thread_id, account_id, from_name/email, to/cc_list(JSONB), subject, body_text, date, has_attachment, category(0-4), urgency(0-2), confidence, created_at
**向量索引**：email_id, embedding(VECTOR(768))
**实体表**：id, email_id, entity_type(person/company/project/amount/date), entity_value, confidence
**推荐记录**：id, user_id, scene_type, trigger_condition, score, status(shown/clicked/dismissed), created_at
### 3.5 模型调度接口
- classify(email): ClassificationResult — 0.5B实时，同步，<500ms
- analyze(email): Promise — 7B深度，异步，队列
- embed(emails): Promise<EmbeddingResult[]> — Embedding，异步，批量
- healthCheck(): ModelStatus — 健康检查
- loadModel/unloadModel(modelType) — 动态加载卸载

## 十四、数据隐私与合规

### 14.1 隐私承诺（技术保障）
- ✅ **原始邮件数据不出本机**：所有 .eml 文件存储在用户本地磁盘，无云端同步
- ✅ **模型推理本地完成**：0.5B / 7B / Embedding 均在本地运行，无 API 上传
- ✅ **零遥测设计**：默认不收集任何使用数据、崩溃报告、性能指标
- ✅ **开源可审计**：核心推理引擎基于开源 llama.cpp，可独立编译验证
- ✅ **用户可控**：云端增强功能默认关闭，开启需二次确认并展示传输内容

```
    - 地址: 北京市**区**路
    
  L3-用户自定义（可配置）：
    - 正则表达式匹配
    - 关键词黑名单
    - 白名单例外（如自己的公司名不脱敏）
```
**脱敏应用范围：**

## 十六、Phase 0 决策分支与 Plan B

Phase 0 的核心目标是验证技术可行性。若关键验证项未通过，按以下分支决策：

```
Phase 0 验证树：
  ├─ W1: PGLite + pgvector 跑通？
  │   └─ ❌ 不通过 → 降级为 SQLite + sqlite-vec，放弃 Postgres 生态
  │
  ├─ W2: 0.5B 分类准确率 > 85%？
  │   └─ ❌ 不通过 → 改用规则引擎主导 + 0.5B 辅助，降低模型依赖
  │
  ├─ W3: 7B 模型本地推理 F1 > 80%？
  │   ├─ ✅ 通过 → 继续 Phase 1
  │   ├─ ⚠️ 边缘（F1 70-80%）→ 增加微调环节（+1周），使用领域数据微调 7B
  │   └─ ❌ 不通过 → Plan B：云端增强通道提前（Phase 1 引入），本地降级为 0.5B + 规则
  │
  └─ W4: 中文搜索 Recall@5 > 60%？
      └─ ❌ 不通过 → 引入 Hybrid Search（BM25 + 向量），或提升 Embedding 模型维度
```

**Plan B 详细方案（7B 本地跑不通时）：**
- 本地层：0.5B 分类 + 规则引擎 + Embedding（仍本地）
- 云端层：7B 精筛 + 周报生成（用户授权后上传脱敏数据）
- 定价调整：专业版降价至 ¥29/月（功能缩水），推出"云端增强包" ¥39/月
- 长期路线：持续优化本地 7B 性能，争取 Phase 2 实现全本地

## 十七、模型选型具体化

| 用途 | 模型 | 尺寸 | 格式 | 推理后端 | 量化方案 |
|------|------|------|------|----------|----------|
| **分类** | Qwen2.5-0.5B-Instruct | 0.5B | GGUF | llama.cpp | Q8_0（精度优先） |
| **深度分析/周报** | Qwen2.5-7B-Instruct | 7B | GGUF | llama.cpp | Q4_K_M（平衡） |
| **Embedding** | BGE-M3 | 0.5B | ONNX | ONNX Runtime | fp16 |
| **脱敏识别** | 复用 7B 模型 | — | GGUF | llama.cpp | Q4_K_M |

**选型理由：**
- **Qwen2.5 系列**：中文能力 SOTA，指令遵循好，社区支持成熟
- **BGE-M3**：支持多语言（含中文），256k 长文本，MTEB 榜单前列
- **GGUF 格式**：llama.cpp 原生支持，跨平台，加载速度快
- **备选方案**：若 Qwen2.5 效果不达预期，可切换至 Llama-3.1-8B-Instruct（英文强，中文稍弱）
